# Bundle the OpenSpec CLI behind a wrap script

Pi OpenSpec lists `@fission-ai/openspec` as a runtime dependency and installs a wrap script named `openspec` in the agent's bin directory (`$PI_CODING_AGENT_DIR/bin`, defaulting to `~/.pi/agent/bin`) from the extension's `session_start` hook. This runs after Pi loads the package on install, update, and startup, including npm installs where lifecycle scripts are disabled. Several shipped skills invoke `openspec` from their shell instructions (validate, list, archive, ...), so the CLI must be reachable wherever the package is installed — a dev-only dependency would never be present in an npm install, and a global `npm i -g` would add an install step and a second, independently versioned copy.

Pi prepends the agent's bin directory to the bash tool's PATH — the same mechanism pi uses for its own `fd`/`rg` binaries — so a file at that path is callable as `openspec` from any skill. The wrap script is a Node script (node shebang) that locates the bundled CLI at run time by resolving `@fission-ai/openspec` from the agent's npm install root, from the current working directory, from npm's default global install location (`npm prefix -g`), and, last, from the package path recorded in Pi's settings — local-path installs never run npm, so the CLI sits under the registered path. No machine-specific paths are embedded, so the script keeps working when the whole agent directory moves to another machine. The package is intended to be installed globally (user scope); the working-directory, global, and settings searches are best-effort fallbacks for other layouts.

The wrap script carries a managed marker line (`@pi-openspec-shim v1 — managed by @hyxi/pi-openspec; do not edit.`). The installer rewrites the file when the marker is present but the content differs (a stale or changed shim), and leaves a marker-less file untouched, so a user's own `bin/openspec` is never clobbered. The installer never fails the package install: if it cannot write the script, it warns and the skills report a missing `openspec` command instead.
